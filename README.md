# Ikanam-schedule

Telegram-бот, который забирает личное расписание студента из личного кабинета РАНХиГС
и отдаёт его тремя способами: текстом в чате, файлом `.ics` и **ссылкой-подпиской**,
которую понимает любой календарь — Google, Apple (iOS/macOS), Android, Outlook.

> **Неофициальный проект.** Не аффилирован с РАНХиГС, не поддерживается академией.

## Зачем это, если у академии есть свой бот

У РАНХиГС действительно есть официальный бот с расписанием и уведомлениями — но он живёт
**только в MAX**. В Telegram аналога нет, и ни один из них не даёт подписки в системный
календарь: расписание нельзя увидеть рядом с личными встречами, нельзя получить
напоминание за 15 минут средствами телефона, нельзя посмотреть с ноутбука или часов.

Этот проект закрывает ровно эти два пробела: **Telegram** и **настоящий календарь**.

## Возможности

- `/today`, `/tomorrow`, `/week` — расписание текстом с аудиториями, корпусами и преподавателями
- `.ics`-файл — разовый импорт в любой календарь
- **Ссылка-подписка** — календарь сам подтягивает изменения, ничего переимпортировать не нужно
- Утренняя сводка в выбранное время
- Пуш при изменении расписания: перенос пары, смена аудитории, отмена
- `/logout` — удаление токена доступа и всех данных о пользователе

## Как устроено

Личный кабинет — это Nuxt-приложение поверх JSON API (`/lk/n-api/...`), поэтому бот
работает с API, а не парсит вёрстку. Это заметно устойчивее: разметка меняется часто,
контракт API — редко.

С адресов дата-центров кабинет перед API ставит JS-проверку антибота. Бот проходит её
настоящим headless Chromium (Playwright): открывает страницу кабинета, исполняет его же
скрипт и дальше ходит в API с полученными cookie. Подделки проверки в проекте нет —
подробности в [docs/api-notes.md](docs/api-notes.md#js-проверка-антибота).

```
Telegram (aiogram)  ─┐
                     ├─→  сервисный слой  ─→  RanepaClient (JSON API ЛК)
HTTP-фид (FastAPI)  ─┘           │
                                 └─→  PostgreSQL: пользователи, снапшоты расписания
                                              │
                             ночной синхрон ──┴──→ diff → пуши об изменениях
```

Ключевые модули:

| Путь | Ответственность |
|------|-----------------|
| `app/ranepa/` | клиент ЛК: авторизация, получение расписания, нормализация в доменные модели |
| `app/calendar/` | сборка `.ics` (файл и фид подписки), таймзоны, `UID`/`SEQUENCE` для корректных обновлений |
| `app/bot/` | команды и диалоги Telegram |
| `app/web/` | HTTP-эндпоинт `/feed/{token}.ics` для подписки |
| `app/core/` | конфиг, шифрование токенов, планировщик, диффер расписания |

## Безопасность и честный дисклеймер

Чтобы обновлять расписание ночью, когда тебя нет в чате, боту нужен доступ к твоему ЛК.
Прямо и без прикрас, что это означает:

- **Пароль не хранится.** Он нужен один раз, при подключении: кабинет отдаёт в ответ refresh-токен, и дальше бот работает только с ним. Сообщение с паролем удаляется из чата сразу после обработки.
- **Хранится refresh-токен** — зашифрованным (Fernet/AES, ключ вне базы, в переменных окружения). Он открывает только твой личный кабинет и перестаёт действовать после `/logout`.
- Шифрование защищает от утечки дампа базы. Оно **не** защищает от того, кто получил доступ к серверу целиком: ключ лежит на том же сервере.
- Владелец инстанса технически может расшифровать токен и прочитать твоё расписание. Доверие к боту = доверие к тому, кто его хостит.
- Не согласен — подними свою копию: `docker compose up -d`, и токен не покинет твой сервер.

`/logout` удаляет токен и все производные данные без остатка.

## Self-host

```bash
git clone https://github.com/Ekanam-Friends/Ikanam-schedule.git
cd Ikanam-schedule
cp .env.example .env      # BOT_TOKEN, CREDENTIALS_KEY, POSTGRES_PASSWORD, DOMAIN, PUBLIC_BASE_URL
docker compose up -d --build
```

Поднимается четыре контейнера: PostgreSQL, бот, сервер подписки и Caddy, который
сам получает сертификат Let's Encrypt для `DOMAIN`. Домен покупать не обязательно —
подойдёт `51-250-1-2.sslip.io` (IP машины через дефисы). Миграции базы применяются
при старте; обновление — `git pull && docker compose up -d --build`.

Пошагово для Yandex Cloud, включая порты и резервные копии: [docs/deploy-yandex.md](docs/deploy-yandex.md).

`CREDENTIALS_KEY` генерируется так:

```bash
python3 -c "import base64,os; print(base64.urlsafe_b64encode(os.urandom(32)).decode())"
```

Хостинг должен быть **в России**: при заходе с зарубежных IP личный кабинет требует капчу.
При этом `api.telegram.org` из России доступен через прокси — укажи его в `TELEGRAM_PROXY`.
Запросы к кабинету через прокси не идут: у двух адресатов противоположные требования,
подробнее в [docs/api-notes.md](docs/api-notes.md).
